# התקנת חדר מצב כסף

אתה מלווה בעל עסק ישראלי — לאו דווקא טכני — בהתקנה. עברית בלבד. **שאלה אחת בכל
פעם**, המתן לתשובה, ורק אז המשך. אל תריץ כלום לפני שהסברת במשפט מה אתה עומד לעשות.

## יש גם דרך בלי שיחה

הדשבורד עצמו פותח מסך הגדרה בפעם הראשונה (http://localhost:8423 → "הגדרה
ראשונית"), ושם המשתמש ממלא סוג עסק, מקדמות, מפתחות Financy וקארדקום. זה כותב
בדיוק את אותם קבצים כמו השלבים כאן (`scripts/lib/setup.mjs`). השתמש בסקיל הזה
כשהמשתמש מעדיף שיחה, או לשלבים 4-7 (משרד ביתי, כיול) שאינם במסך.

## כלל ברזל — סודות

את מפתחות Financy אתה שומר **אך ורק** דרך `saveSecret` (פקודה בשלב 3). לעולם אל
תדפיס אותם חזרה, אל תכתוב אותם לקובץ אחר, ואל תשמור אותם בשום מקום נוסף.

## שלב 0 — הגנה מפני דריסה

בדוק אם כבר הוגדר: `node -e "const s=require('./config/settings.json');console.log(s.entityType)"`
אם התוצאה אינה `null` — ההתקנה כבר רצה. שאל במפורש אם לערוך מחדש, ואל תיגע בכלום
בלי אישור.

## שלב 1 — סוג הישות

שאל: **"איזה סוג עסק אתה? עוסק פטור, עוסק מורשה, או חברה בע"מ?"**

| תשובה | entityType | vatRate | הערה למשתמש |
|---|---|---|---|
| עוסק פטור | `patur` | `1.0` | אין מע"מ — ההכנסות יוצגו כפי שהן. יש תקרת מחזור (ראה config/tax-brackets.json → osekPatur) |
| עוסק מורשה | `murshe` | `1.18` | |
| חברה בע"מ | `company` | `1.18` | |

לעוסק (פטור/מורשה) אמור: *"פאנל המס יחשב לפי מדרגות מס אישיות, נקודות זיכוי
וביטוח לאומי לעצמאי. שים לב — דמי ביטוח לאומי משולמים במקדמות נפרדות לביטוח
לאומי; שיעור המקדמה שהפאנל גוזר מכסה מס הכנסה בלבד."*

## שלב 2 — שיעור המקדמה

שאל: **"מה שיעור מקדמות מס ההכנסה שקבעו לך? (מופיע בפנקס המקדמות או אצל הרו"ח.
אם אין לך מושג — נדלג ותשלים אחר כך)"**

מספר בין 0 ל-15 בערך. אם לא יודע — השאר `null` והמד יציג '···'.

**לעוסק (פטור/מורשה) שאל גם:** "כמה נקודות זיכוי יש לך? (מופיע בשומה או אצל
הרו"ח. כל תושב מקבל לפחות 2.25; אישה 2.75; ילדים ושירות מוסיפים)". אם לא
יודע — `null`, והמנוע יחשב לפי מינימום תושב 2.25 ויאמר זאת.

**לעוסק מורשה/חברה שאל גם:** "דיווח מע"מ חודשי או דו-חודשי?" מחזור שנתי מעל
₪1,775,000 = חודשי. אם לא יודע, השאר `null` והדשבורד יחליט לפי המחזור. ו"עד
איזה יום בחודש?" 15 כרגיל; מדווחים בדיווח מפורט (874) עד ה-23.

כתוב את שלבים 1+2 יחד:
```bash
node -e "
const fs=require('fs'); const f='config/settings.json';
const j=JSON.parse(fs.readFileSync(f));
j.entityType='murshe';        // מהתשובה בשלב 1
j.vatRate=1.18;               // לפי הטבלה
j.advanceRatePct=5;           // מהתשובה בשלב 2, או null
j.creditPoints=null;          // נקודות זיכוי — לעוסק; לחברה השאר null
j.flagThresholdIls=5000;      // מהתשובה על גודל התנועה החריגה
j.vatPeriodMonths=null;       // 1 / 2 / null=לפי מחזור
j.vatDueDay=15;               // 15 או 23
fs.writeFileSync(f, JSON.stringify(j,null,2)+'\n');
console.log('נכתב');"
```

**שאל גם:** *"מאיזה סכום תנועה בחשבון היא חריגה בעיניך ושווה התראה?"* וכתוב
ל-`flagThresholdIls`. ברירת מחדל 5,000. עסק שמעביר סכומים גדולים כדבר שבשגרה
יבחר גבוה יותר, אחרת פאנל ההתראות יתמלא ברעש.

## שלב 3 — חיבור Financy

שאל אם כבר יש לו חשבון Financy. אם לא — הפנה: זהו שירות open-finance **בתשלום**,
נרשמים, מחברים את חשבונות הבנק והכרטיסים דרך תקן הבנקאות הפתוחה, ומקבלים שלושה
מפתחות: client id, client secret, user id. חכה שיחזור איתם.

בקש את שלושת הערכים, ושמור — **בפקודה אחת, בלי להדהד אותם**:
```bash
FINANCY_CLIENT_ID='<ערך>' FINANCY_CLIENT_SECRET='<ערך>' FINANCY_USER_ID='<ערך>' \
node -e "
import('./scripts/lib/secrets.mjs').then(m=>{
  for (const k of ['FINANCY_CLIENT_ID','FINANCY_CLIENT_SECRET','FINANCY_USER_ID']) {
    if (!process.env[k]) throw new Error('חסר '+k);
    console.log(k, '→', m.saveSecret(k, process.env[k]));
  }
});"
```
במק זה נכנס ל-Keychain; בלינוקס/ווינדוס לקובץ `.env` (מוגן, מחוץ ל-git).

שאל גם: **"כמה רענונים בחודש כלול במסלול שלך ב-Financy?"** וכתוב את המספר ל-
`financyMonthlyRefreshCap` ב-`config/settings.json` (ברירת מחדל 30 אם לא יודע).

**ושאלה שנייה, חשובה:** *"יש עוד משהו שמרענן את אותו חשבון Financy? אפליקציה
נוספת, MCP, סקריפט או cron?"* אם כן, כתוב `financyRefreshEnabled=false`.
המכסה נספרת מקומית מתוך `sync_log` של ההתקנה הזו בלבד, ואינה יודעת על צרכנים
אחרים. שני מרעננים על חשבון אחד שורפים את הקרדיטים פי שניים, והדשבורד עדיין
יקרא את הנתונים המעודכנים שהצרכן השני משך.

## שלב 3ב — חיבור קארדקום (אופציונלי)

שאל: **"אתה סולק דרך קארדקום?"** אם לא, דלג. פאנל המכירות יישאר מוסתר.

אם כן: צריך משתמש API לטרמינל. בממשק קארדקום: הגדרות → משתמשי API → משתמש
חדש עם הרשאת **קריאה בלבד** (ListTransactions). מקבלים שם משתמש וסיסמה.
שמור אותם **בפקודה אחת, בלי להדהד**:
```bash
CARDCOM_API_NAME='<ערך>' CARDCOM_API_PASSWORD='<ערך>' \
node -e "
import('./scripts/lib/secrets.mjs').then(m=>{
  for (const k of ['CARDCOM_API_NAME','CARDCOM_API_PASSWORD']) {
    if (!process.env[k]) throw new Error('חסר '+k);
    console.log(k, '→', m.saveSecret(k, process.env[k]));
  }
});"
```

ואז הפעל את המודול:
```bash
node -e "
const fs=require('fs'); const f='config/cardcom.json';
const j=JSON.parse(fs.readFileSync(f)); j.enabled=true;
fs.writeFileSync(f, JSON.stringify(j,null,2)+'\n');"
```

שאל: **"בדף הסליקה שלך, באיזה שדה מותאם (CustomField) נכנס שם המוצר?"** ברירת
המחדל 24. אם לא יודע, השאר 24 ותבדוק אחרי הסנכרון הראשון: עסקאות בלי שם
יופיעו כ-"אחר" עם סימן ⁇. אפשר למפות סכום קבוע לשם ב-`amountNames` (למשל
`"199": "מנוי חודשי"`), אבל **רק** סכום שמשרת מוצר אחד בלבד.

`npm run sync` מושך גם קארדקום (7 ימים אחורה בפעם הראשונה, ומשם רק היום).
לטעינה היסטורית: `npm run sync:cardcom -- --backfill 90`.

**התאמה לבנק:** שאל "תוך כמה ימים הזיכוי של קארדקום נכנס לבנק, ואיזו עמלה
מנוכה מראש?" וכתוב ל-`settlement.lagDays` ו-`settlement.feePct` ב-`config/cardcom.json`.
אם הכסף מגיע מחברת האשראי פעם בחודש (למשל ישראכרט ב-15): `mode:"monthly"`,
`dayOfMonth:15`. אחרי הסנכרון הראשון, פאנל "התאמת סליקה ↔ בנק" יראה אם הזיכויים
מזוהים; אם לא, הוסף ל-`settlement.keywords` את הטקסט שמופיע בבנק.

**פרטיות:** הסקריפט שומר רק מזהה עסקה, זמן, סכום ושם מוצר. שם הלקוח, ת"ז,
טלפון ומייל לא נשמרים ולא מודפסים.

## שלב 4 — משרד בבית

שאל: **"יש לך משרד בתוך הבית?"** אם כן: **"מה היחס בין שטח המשרד לשטח הדירה,
בערך? (למשל רבע = 0.25)"**

```bash
node -e "
const fs=require('fs'); const f='config/tax-rules.json';
const j=JSON.parse(fs.readFileSync(f));
j.homeOffice.businessRatio=0.25;   // מהתשובה; אם אין משרד ביתי — השאר null
fs.writeFileSync(f, JSON.stringify(j,null,2)+'\n');"
```

אמור: *"ארנונה, ועד בית, חשמל ומים יוכרו לפי היחס הזה. שים לב — דרישת חלק
מהדירה כהוצאה עלולה להשפיע על פטור ממס שבח במכירה. שווה לאשרר עם רו"ח."*

## שלב 5 — צבע לעסק (לא חוסם)

שאל בקצרה: עובדים? רכב בבעלות העסק? תחומי ההוצאה הגדולים? אל תשנה קונפיג לפי
זה עכשיו — רשום לעצמך את התשובות; הן ישמשו לכיול חוקי הסיווג אחרי הסנכרון
הראשון, כשרואים תנועות אמיתיות.

## שלב 6 — הרמה

```bash
npm install
npm run sync        # הסנכרון הראשון — ימשוך עד 35 יום אחורה, ייקח דקה-שתיים
npm run dev         # http://localhost:8423
```

אם `npm run sync` נכשל על מפתחות — חזור לשלב 3. אם על רשת/ספק — הצע
`npm run sync -- --no-refresh` ונסה שוב מאוחר יותר.

פתח למשתמש את http://localhost:8423 והסבר בשלושה משפטים מה הוא רואה: תזרים
ויתרות, רווח והפסד חודשי עם בורר חודשים, ופילוח הוצאות (ואם חיברת קארדקום: מכירות
היום / אתמול / שלשום / 7 ימים, עם בחירת תאריך). **על פאנל המס אמור
במפורש: זו הערכה בטווח, לא ייעוץ — המספרים ב-`config/tax-brackets.json` מחכים
לאישור רו"ח (`verifiedBy`).**

## שלב 7 — כיול ראשון (אחרי שיש נתונים)

הצע לעבור יחד על "לא מסווג" בפאנל ההוצאות: לכל ספק שחוזר, הוסף חוק ל-
`config/rules.json` או `config/expense-rules.json`. עצור אחרי 5-6 חוקים —
עדיף כיול הדרגתי על פני ניחוש גורף. אם עלו עובדים/רכב בשלב 5, ודא שהקטגוריות
המתאימות קיימות.

**כרטיסי אשראי, חובה לעבור על זה:** הצג את `cardIssuers` ב-`config/rules.json`
ואמור: *"חיוב מרוכז מהמנפיקים האלה נחשב סגירת כרטיס ולא הוצאה, כי ההוצאה כבר
נספרת מתנועות הכרטיס עצמו."* ואז ודא מול המשתמש אילו כרטיסים באמת מחוברים
ל-Financy. **מנפיק שהכרטיס שלו לא מחובר, חייב לצאת מהרשימה**, אחרת ההוצאה
תיעלם מהדוח לגמרי: החיוב המרוכז הוא הרישום היחיד שלה. ולהפך, מנפיק שמחובר ולא
ברשימה יגרום לספירה כפולה. בדוק מה יוצא בפועל:

```bash
node -e "
const db=require('better-sqlite3')('data/money.db',{readonly:true});
console.log(db.prepare(\"SELECT DISTINCT account_type, account_number, provider FROM bank_transactions\").all());
console.log(db.prepare(\"SELECT counterparty, bucket, COUNT(*) n FROM bank_transactions WHERE account_type='CHECKING' AND amount<0 AND bucket='card_settlement' GROUP BY counterparty, bucket\").all());"
```

**עובדים, ספקים והחזרים:** `team`, `suppliers` ו-`refundPairs` ב-
`config/rules.json` נשלחים ריקים בכוונה. מלא אותם עכשיו מתוך הנתונים של
המשתמש. `refundPairs` הוא לקוחות שקיבלו החזר בפועל, ו-`suppliers` הוא מי
שלעולם אינו החזר (עו"ד, רו"ח, קבלן). **הקבצים האלה יושבים בתוך ריפו גיט. אם
המשתמש יעלה אותו לגיטהאב, השמות עולים איתו** — אמור לו את זה במפורש.

בסוף אמור: הסנכרון ידני (`npm run sync`), מומלץ פעם ביום-יומיים, והכל נשאר
מקומי — שום נתון לא יוצא מהמחשב.
