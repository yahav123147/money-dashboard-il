# חדר מצב כסף

דשבורד פיננסי מקומי לעסק ישראלי. רץ על המחשב שלך, הנתונים לא יוצאים ממנו.

עונה על שלוש שאלות שרוב העסקים הקטנים לא יודעים לענות עליהן באמצע השנה:

1. **כמה באמת נשאר לי החודש** — הכנסות פחות הוצאות, מסווג אוטומטית מתנועות הבנק
2. **על מה יוצא הכסף** — פילוח הוצאות לקטגוריות, עם הספקים הגדולים
3. **כמה מזה באמת חייב במס** — הגשר מתזרים להכנסה חייבת, לפי כללי ההכרה בישראל

## למי זה מתאים

עוסק פטור · עוסק מורשה · חברה בע"מ. ההתקנה שואלת מה אתה, ומכוונת את הדשבורד בהתאם —
לעוסק פטור אין מע"מ ויש התראת תקרה, לחברה יש מס חברות ומשיכות בעלים.

## התקנה

צריך Node 20+.

```bash
git clone <this-repo> && cd money-dashboard-il
npm install
npm run dev
```

פתח http://localhost:8423. בפעם הראשונה הדשבורד פותח **מסך הגדרה** במקום נתונים:
סוג העסק (פטור / מורשה / חברה), שיעור המקדמות, מפתחות Financy לבנק, ואם יש,
מפתחות קארדקום לסליקה. לוחצים "שמור", הסנכרון הראשון רץ (דקה-שתיים), והדשבורד
נפתח עם כל הנתונים. כפתור "הגדרות" בכותרת מחזיר למסך הזה בכל רגע.

המפתחות נשמרים ב-Keychain במק, או בקובץ `.env` מוגן (מחוץ ל-git) בלינוקס/ווינדוס.
הם לא נכתבים לשום קובץ קונפיג ולא מוחזרים לדפדפן.

**מעדיף להתקין בשיחה?** עם [Claude Code](https://claude.com/claude-code) מותקן,
`claude` ואז `/setup`: אותן שאלות, פלוס כיול ראשון של חוקי הסיווג מול התנועות
האמיתיות.

## מאיפה מגיעים הנתונים

**דרך בנקאות פתוחה (Open Finance), עם [financy](https://www.npmjs.com/package/financy).**
נרשמים ל-Financy (שירות בתשלום — חשבון נפרד לכל עסק), מחברים את חשבונות הבנק
דרך התקן הבנקאות הפתוחה, ומקבלים שלושה מפתחות. סקיל ההתקנה שומר אותם ומכאן
הסנכרון רץ לבד:

```bash
npm run sync
```

הנתונים עוברים ישירות מהבנק אליך דרך שירות מורשה. הדשבורד עצמו לא שולח כלום
לאף אחד, הוא קורא מקומית בלבד. הטלמטריה של Next מכובה מפורשות בסקריפטים
(`NEXT_TELEMETRY_DISABLED=1`), ו-CLI של Financy מוצמד לגרסה מדויקת ב-
`package.json` ורץ מ-`node_modules` בלבד, לא נמשך מהרשת בזמן ריצה.

**אם משהו אחר כבר מרענן את אותו חשבון Financy** (אפליקציה נוספת, MCP, cron):
קבע `financyRefreshEnabled: false` ב-`config/settings.json`. מכסת הרענונים
נספרת מקומית ואינה יודעת על צרכנים אחרים, ושני מרעננים על חשבון אחד שורפים
קרדיטים כפול.

**לפני שמעלים את התיקייה לגיטהאב:** `config/rules.json` ו-
`config/expense-rules.json` מתמלאים בשמות אמיתיים של עובדים, ספקים ולקוחות
שקיבלו החזר. הם קבצי גיט לכל דבר. ריפו ציבורי יפרסם אותם, וגם מחיקה מאוחרת
משאירה אותם בהיסטוריה.


## מכירות מקארדקום (אופציונלי)

אם אתה סולק דרך קארדקום, הדשבורד מציג גם פאנל **מכירות**: היום, אתמול, שלשום,
7 ימים אחרונים, או כל תאריך שתבחר, עם פילוח לפי מוצר. `/setup` שואל אם
לחבר; צריך משתמש API לטרמינל עם הרשאת קריאה. המפתחות נשמרים כמו של Financy
(Keychain במק, `.env` מוגן בלינוקס/ווינדוס), והגדרות המודול ב-`config/cardcom.json`.

נשמרים רק מזהה עסקה, זמן, סכום ושם מוצר. פרטי הלקוח לא נכתבים לדיסק.

```bash
npm run sync                          # בנק + קארדקום (היום)
npm run sync:cardcom -- --backfill 90 # טעינה היסטורית
```

## מצב הדגמה — ללמד בלי לחשוף כלום

רוצים להראות את הדשבורד למישהו, להקליט סרטון, או ללמד סדנה — בלי נתונים אמיתיים?

```bash
npm run demo && npm run dev
```

זה מייצר **עסק פיקטיבי** — 8 חודשים של תנועות מציאותיות שנספרים אחורה מהיום,
לקוחות מומצאים, מסים, פרסום ותוכנות — שמדליק כל פאנל בדשבורד. הנתונים דטרמיניסטיים: כל הרצה מייצרת
בדיוק את אותם מספרים, אז הקלטה ושידור חי תמיד יתאימו.

שלושה תסריטים:

```bash
npm run demo                        # עוסק מורשה — הסיפור המלא
npm run demo -- --entity=patur     # עוסק פטור מתקרב לתקרה → מדגים את ההתראה
npm run demo -- --entity=company   # חברה בע"מ — מס חברות ומשיכות בעלים
```

מצב ההדגמה **מסרב לרוץ** אם יש כבר נתונים או קונפיג — הוא לא יידרוס עסק אמיתי.
איפוס: `git checkout config/ && rm -f data/money.db*`

## מה זה לא

**זה לא ייעוץ מס וזה לא תחליף לרואה חשבון.**

שכבת המס מציגה **הערכה בטווח**, לא מספר. היא מסתמכת על אחוזי הכרה שנכונים לכלל
המקרים, ועל נתונים שהיא רואה בלבד — הוצאה ששולמה מכרטיס שלא חיברת פשוט לא קיימת
מבחינתה. מדרגות המס ושיעורי הביטוח הלאומי ב-`config/tax-brackets.json` נושאים
מקור ודגל אמינות, ו-`verifiedBy` נשאר ריק עד שרואה חשבון מאשר אותם.

אל תגיש דוח על סמך מספר מהכלי הזה בלי לאמת אותו.

## מבנה

```
config/          כל הכיול. זה מה שהופך את זה לשלך
  rules.json         סיווג תנועות בנק — ברירות מחדל ישראליות
  expense-rules.json קטגוריות הוצאה
  tax-rules.json     אחוזי הכרה + יחס המשרד בבית
  tax-brackets.json  מדרגות מס, נקודות זיכוי, ביטוח לאומי — לפי שנה
  settings.json      מע"מ, שיעור מקדמה
  cardcom.json       חיבור קארדקום (אופציונלי)
lib/queries.js   כל צד הקריאה
scripts/lib/setup.mjs  ההגדרה הראשונית (מסך בדשבורד + /setup)
scripts/lib/     סיווג, סכמה, כללי מס
components/      הפאנלים
```
